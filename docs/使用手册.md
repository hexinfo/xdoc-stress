# x-doc 核心链路压测工具 · 使用手册

**版本**：v0.3.4
**适用平台**：Linux（x86_64 / aarch64）、Windows（x64）
**仓库**：https://github.com/hexinfo/xdoc-stress

---

## 1. 简介

沿前端真实请求链测度 x-doc 影像控件的转换性能，按用户使用流程逐步计时。

**链路**：

```
上传 → prepare（登记+触发转换）→ state 循环（轮询至就绪）→ range / excel 全页拉取
```

**指标**：

| 指标 | 含义 |
|---|---|
| 上传 | 文件上传到宿主 ECM 的耗时 |
| 就绪 | prepare 发起 → state 首次返回就绪（转换完成） |
| 下载 | 后端自报的源文件下载净耗时（metric.download） |
| 转换 | 后端自报的格式转换净耗时（metric.convert） |
| 首页 | 就绪后首个 range 请求的耗时（首屏渲染关键路径） |
| 全页 | 首次 range 到拉完文件尾部（从第一页翻到最后一页） |
| 端到端 | 以上全部之和（用户点开到看完全文的墙钟总时间） |

## 2. 下载与安装

从 [GitHub Releases](https://github.com/hexinfo/xdoc-stress/releases) 下载对应平台产物：

| 文件 | 平台 | glibc | 大小 |
|---|---|---|---|
| `xdoc-stress_*_linux-x86_64.tar.xz` | Linux x86_64（UOS 20 / 麒麟 V10） | ≥ 2.28 | ~4MB |
| `xdoc-stress_*_linux-aarch64.tar.xz` | Linux arm64（飞腾 / 鲲鹏） | ≥ 2.28 | ~4MB |
| `xdoc-stress_*_windows-x64.exe` | Windows 10/11 x64 | — | ~9MB |

### Linux 安装

```bash
tar -xJf xdoc-stress_*_linux-x86_64.tar.xz
chmod +x xdoc-stress
./xdoc-stress
```

无额外依赖，不需要 root 权限，解压即用。

### Windows 安装

直接双击 `.exe` 运行，无需安装。

## 3. 图形界面使用

### 3.1 界面布局

```
┌──────────┬──────────────────────────┬──────────┐
│  文件列表  │        结果表              │  配置     │
│          │                          │          │
│ [文件夹…] │  # 文件 页 上传 就绪 … 状态  │ BASE_URL │
│ [文件…]   │  1 a.pdf 2 45ms 1.0s … ✓ │ AUTH     │
│          │                          │ 并发/轮次  │
│ ☑ 全选   ├──────────────────────────┤ 拉取/轮询  │
│ [清空]    │        运行日志            │          │
│          │  ✅ a.pdf#1 upload=45ms…   │ [开始▶]  │
│          │  ✅ b.pdf#2 upload=12ms…   │ [停止■]  │
└──────────┴──────────────────────────┴──────────┘
│                    状态栏：3/3 成功 · 吞吐 85.2 件/min          │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 操作步骤

1. **添加文件**：点「📁 文件夹…」选择整个目录，或「📄 文件…」选择单个文件
   - 隐藏文件（`.DS_Store`、`._*`）自动过滤
   - 重复添加的文件自动去重
2. **配置目标**：右侧面板填写
   - **BASE_URL**（必填）：宿主网关地址，如 `http://172.21.0.26:8080/dvs`
   - **AUTH_TOKEN**（可选）：Bearer token
   - **AUTH_HEADERS**（可选）：JSON 格式的自定义头
3. **调整参数**（可选）：
   - 并发线程数（默认 1）
   - 每文件轮次（默认 2：第 1 轮冷启动预热，第 2 轮起为稳定数据）
   - range 分段字节（默认 1MB）
   - state 轮询间隔 / 上限
4. **开始测试**：点「▶ 开始测试」
5. **查看结果**：结果表实时逐行显示，日志面板同步滚动
6. **停止**：点「■ 停止」中断在跑任务（已完成的保留）
7. **导出**：点「📋 复制」粘到 Excel，或「⬇ CSV」保存文件

### 3.3 配置持久化

所有配置（BASE_URL、AUTH、并发参数等）自动保存，重启应用后自动恢复。文件列表不记忆（每次打开为空）。

### 3.4 鉴权示例

| 场景 | AUTH_TOKEN | AUTH_HEADERS |
|---|---|---|
| Bearer token | `eyJhbGciOi...` | 留空 |
| Cookie 会话 | 留空 | `{"Cookie":"JSESSIONID=abc123"}` |
| 自定义 token 头 | 留空 | `{"X-Auth-Token":"xxx"}` |
| 租户头 + Cookie | 留空 | `{"Cookie":"sid=x","Xms-Tenant-Id":"1001"}` |

## 4. 结果解读

### 5.1 状态标记

| 标记 | 含义 | 说明 |
|---|---|---|
| ● | 预热轮 | 该文件的第 1 轮，引擎冷启动耗时偏慢属正常 |
| ✓ | 成功 | 稳定轮完成 |
| ✗ | 失败 | 附错误原因（连接拒绝 / 超时 / 转换失败等） |

### 5.2 统计口径

- **汇总统计自动剔除预热轮**（●），只计稳定轮（✓）
- 吞吐 = 稳定成功数 ÷ 墙钟耗时（件/分钟）
- 全部是预热轮时退回全量统计

### 5.3 时间列关系

```
就绪耗时 ≥ 下载耗时 + 转换耗时    ← 轮询间隔引入的量化噪声
端到端 ≈ 上传 + 就绪 + 全页        ← 各步骤间隙计入端到端
```

## 5. 编译构建

### 6.1 环境要求

- Rust ≥ 1.75（`rustup install stable`）
- Linux 编译：Docker（容器内编译，无需本地安装交叉工具链）
- Windows 编译：Visual Studio Build Tools（MSVC）

### 6.2 本地编译

```bash
# macOS / Linux 直接编译
cargo build --release --manifest-path src-slint/Cargo.toml

# CLI 版
cargo build --release --manifest-path src-cli/Cargo.toml
```

### 6.3 Linux 打包（glibc 2.28）

```bash
# Slint GUI 版（Debian 10 容器编译，兼容 UOS 20 / 麒麟 V10）
bash scripts/pack-slint-linux.sh x86_64
bash scripts/pack-slint-linux.sh aarch64
```

### 6.4 GitHub Actions 自动编译

```bash
git tag v0.x.y
git push origin v0.x.y
```

自动触发三平台编译并发布到 Releases。

## 7. 常见问题

**Q: 为什么所有结果都是 `—`？**
A: 后端服务未启动或 BASE_URL 不对。检查目标地址能否访问。

**Q: 日志面板为什么是空的？**
A: 同上——请求失败时引擎会生成失败行但不会有详细日志。确认后端在跑再试。

**Q: 首轮耗时明显偏慢？**
A: 正常现象（● 预热轮），后端 JVM/Spire 引擎首次转换需要加载类、初始化字体。稳定数据看第 2 轮起。

**Q: Linux 上提示 glibc 版本过低？**
A: 本工具要求 glibc ≥ 2.28（Debian 10 / Ubuntu 18.04+）。更老的系统请升级或使用 CLI 版。

**Q: 如何清除配置重新开始？**
A: 删除应用数据目录下的 `xdoc-stress-config` 文件（Slint localStorage），或直接修改 UI 里的值。

**Q: 并发数设多少合适？**
A: 参考性能测试方案 C-05 梯度：5 → 10 → 20 → 50，观察就绪时间是否衰减。
